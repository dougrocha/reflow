01 / THE CONVERSION

What happens to a document?

The Python CLI converts the PDF, and the browser later reads the files it writes. The stages below follow convert.py. Review is an output of the conversion, not a step that blocks rendering.

Open and repair

Keep the input byte for byte. qpdf, through pikepdf, repairs a working copy, decrypts it with a supplied password, and linearizes it. Every later stage reads that copy.

working.pdf

Inspect pages

Read the source metadata, hash the input, measure the pages, and classify each page by its text and image coverage. When OCRmyPDF is installed, OCR the pages that hide text in their images, each in the mode its reason needs.

Document + PageInfo

Find structure

The selected engine finds text blocks, reading order, headings, lists, tables, figures, and artifacts.

Node tree

Check and describe

Compare the result with the tag tree and bookmarks, assign unique IDs, and crop figures. On request, ask a model the narrow questions that the rules cannot settle.

Facts + figure attributes

Render outputs

Write HTML chunks, navigation data, the document tree, review items, passages for questions, optional page images, and traces.

Output directory

Read and review

Open the static HTML, or load the files in the web viewer. Compare the decisions in the transcript with the page image.

Viewer + inspector
Two views of the same source. Extraction and rendering read the working copy. Ingest reads the source metadata and classifies the pages from the supplied PDF. A page image keeps the appearance, and the transcript gives the inferred reading structure.
02 / INPUTS & ENGINES

Different pages need different treatment.

Page classification describes what a page holds. With --ocr auto, the default, OCRmyPDF adds a text layer when it is installed. It reads image-only pages, pages of unreadable text, and the textless parts of a page image in an untagged document. It redoes the text layer, which keeps the images and visible text, and rasterizes a page only when its visible text is outlined or unreadable. Without OCRmyPDF, each image-only page gets an error in the review, and each unread part of a page image a warning.

Born digital

Text already exists

Reports, directories, and research papers usually have extractable text. The analyzer reads the structure from fonts, positions, images, and drawing objects.

Watch for columns, running headers and footers, table spans, and ambiguous headings.

Mixed

An image with a text layer

A page with text and with images over at least 90% of its area is mixed. A scan with a readable OCR layer keeps it, because Tesseract can read it worse.

Watch for OCR mistakes, lost characters, and wrong word order.

Scanned or empty

No extractable text

A page with no text is scanned when images cover at least 20% of it, and empty otherwise. These are simple coverage rules, not a judgment of what the page means.

Current limit. Without OCRmyPDF, reflow does not transcribe text that exists only as an image. Hybrid does not send scanned or empty pages to Docling.

Choose the layout engine

Heuristic · the default

Extract text and objects with PDFium, detect candidate tables with pdfplumber, then apply layout rules. No Docling models are required.

All pages → Text + table extraction → Layout rules → Nodes
All three engines, without the selector

Heuristic. PDFium extracts the text, pdfplumber detects tables, and then layout rules apply. Hybrid. The heuristic analysis runs first. Pages with soft column splits, detected tables, vector figures, or fragmented text go to Docling. The heuristic text and reading order stay. A Docling table or figure replaces the heuristic one only when it keeps the page's text. Docling. The ML adapter analyzes the document and converts its results to the same Node model. Docling and hybrid need the optional Docling dependencies. The device choices are auto (cuda, then mps, else cpu), cuda, mps, and cpu. Naming a GPU that is not available is an error.

03 / THE SHARED LANGUAGE

The document tree connects everything.

Every engine produces the same model. Rendering, review, and inspection read meaning and page coordinates from it, so they never extract from the PDF again.

A document becomes nested nodes

Document
├── metadata: title, language, source hash…
├── pages: size, rotation, kind, text count…
└── root: doc
    ├── h1 → document title
    ├── h2 → section heading
    ├── p  → paragraph
    ├── list
    │   └── li → list item
    ├── table
    │   └── tr → row
    │       ├── th → header cell
    │       └── td → data cell
    ├── figure
    │   └── caption
    └── artifact → running header / footer

One example node

{
  "id": "7:example",
  "role": "figure",
  "page": 7,
  "bbox": [72, 120, 360, 300],
  "text": null,
  "attrs": { "needs": "alt" },
  "confidence": 0.4,
  "source": "heuristic",
  "children": []
}

Page. The 1-based PDF index. Box. [left, top, right, bottom] in PDF points, measured from the top-left corner. ID. Built from the page, the rounded box, and the text. Duplicate IDs are made unique.

Source and confidence. These record where a decision came from and whether it needs a closer look. Through data-node, the IDs link page overlays to transcript blocks.

04 / THE OUTPUT CONTRACT

One directory. Several consumers.

A conversion writes a static bundle. Reading, navigation, visual comparison, and diagnostics each have their own files.

File or folderWhat it containsWho uses it
original.pdfThe input, byte for byte.Readers downloading the PDF.
working.pdfThe repaired and linearized working copy, decrypted when a password is supplied.Every processing stage after ingest.
index.htmlThe static reading shell, with the contents and the first chunk inline.Readers. The bundled JavaScript loads the other chunks.
chunks/0001.htmlStandalone HTML pages with semantic transcript blocks and page wrappers.No-JavaScript readers and both viewer implementations.
manifest.jsonCompact v2 metadata: title, language, page sizes, label offset, sparse overrides, chunk ranges, contents, and text-size estimates.The framework-independent web viewer core.
toc.jsonFull heading list with page, level, and chunk anchor.Navigation, and the full contents when the manifest has a shortened list.
document.jsonSerialized metadata, pages, and the complete semantic tree.Inspector and integrations that need all nodes.
review.jsonErrors and warnings, with node IDs, boxes, source, confidence, and text excerpts.Review dashboard and inspector.
figures/*.webpCropped figure images, referenced by the HTML.Transcript readers and the optional description provider.
pages/0001.webpRenderings of the original pages. --no-page-images leaves them out.Original view and visual comparison.
trace/0001.jsonLine-level diagnostics of the heuristic analysis: dropped artifacts, column splits, and gutters. Written only when the selected engine supplies trace data.Inspector and developers debugging layout.
layout/Per-page layout records: the boxes and roles the inspector draws.Inspector.
passages.jsonlRetrievable passages: paragraphs, notes, captions, list items and table rows, with page, box and headings."Ask a question" in the web app.
alt-text-cache.jsonOptional cached descriptions keyed by figure bytes, context, provider, and prompt version.Later conversions that draft figure descriptions.
ai-assist-cache.jsonCached answers to the questions of the opt-in assist.Later conversions with the assist on.
assets/Bundled vanilla viewer CSS and JavaScript.The generated static HTML reader.
Why chunks? A chunk holds whole pages. The first chunk stays within about 30,000 characters, because the viewer fetches it first. A later chunk ends at a page boundary once it reaches 150,000 characters, or at a page that opens a top-level section once it has 40,000. These targets count characters and are soft, so a large page can exceed them, and non-ASCII text takes more bytes than characters. The browser can fetch the chunk that holds a requested page.
05 / HUMAN JUDGMENT

Read the result. Inspect the decisions.

1. Review the queue

Every fact with a severity becomes an error or a warning. So does every node whose confidence falls below the threshold for its role. The confidence of a node is scored from its facts.

A missing figure description is an error. A generated description stays a suggestion to check.

2. Compare the page

The inspector puts the original page image, the bounding boxes, the node roles, the transcript, and any heuristic traces together. Deep links keep the selected page and issue.

Use it to find missing text, misleading structure, and uncertain figures.

3. Check meaning

Check the reading order, the heading levels, the table headers, and whether image descriptions carry the useful information. The current UI is for inspection. Saved edits that override the conversion are on the roadmap.

Conversion writes output even when review items remain.

What does the local AI description do?

--alt-text local runs the local Qwen3-VL provider through transformers, on the device that --device picks. CPU works but is slow. The model sees the cropped image with its caption, the heading before it, and the paragraph context. It drafts alt text, and it may mark a figure as decorative or add a longer description. Each result carries source=llm and a warning for human review. The model dependencies and weights must be installed.

06 / THE READING EXPERIENCE

Two viewers, one set of converted files.

Static output

Python writes HTML and vanilla JavaScript

index.html includes the first chunk, and the bundled viewer loads the rest. Without JavaScript, the standalone chunk pages are the fallback for reading.

index.html → chunks + assets
Next.js app

A headless core reads the manifest for React

web/src/reflow/core.ts normalizes the manifest and splits fetched chunks into per-page HTML. React bindings load the pages and show the transcript or the original images.

manifest.json → core.ts → DocumentViewer

The sample app has document overviews at /docs/<slug>, reading at /view/<slug>, inspection at /inspect/<slug>, a review dashboard at /review, and conversion jobs (rebuild, queue, cancel, retry) at /builds. The sidebar of the viewer answers a question from the document with a quote and its page. A local Ollama model reads the passages by default, or the Anthropic API with your own key. The build script of the app converts the sample documents into web/public/docs/<slug>/ and copies the source PDFs into web/public/pdfs/. It converts into a temporary directory and swaps in the output only when the conversion succeeds.

07 / TRY THE PROJECT

From a local PDF to a browser.

Run Python commands from the repository root. Start with a small text-based sample, then compare the transcript against its original pages.

Inspect and convert

# Install the Python environment
uv sync

# Download samples/resnet.pdf from arxiv.org (once; it is not committed)
uv run python scripts/fetch_samples.py

# Inspect metadata and page types
uv run reflow inspect samples/resnet.pdf

# Save the ingest model, before layout
uv run reflow inspect samples/resnet.pdf \
  --json -o /tmp/resnet-ingest.json

# Convert with the default heuristic engine
uv run reflow convert samples/resnet.pdf \
  -o /tmp/reflow-resnet

# Serve the generated static bundle
python3 -m http.server 8000 \
  --directory /tmp/reflow-resnet

Open localhost:8000 while the server runs. To inspect or convert an encrypted input, set REFLOW_PDF_PASSWORD or add --password without a value for a hidden prompt (also supported by audit). --password <value> still works but warns that the password is visible in the process list. The inspect JSON has the metadata and page information. The document.json of a conversion also has the analyzed content tree.

Try ML layout or the sample app

# Optional ML dependencies
uv sync --extra docling

# Hybrid layout using CPU
uv run reflow convert samples/resnet.pdf \
  -o /tmp/reflow-hybrid \
  --engine hybrid --device cpu

# Sample website (from web/)
cd web
bun install
bun run docs:build resnet fw9
bun run dev

Open the URL that Next.js prints. Without slugs, bun run docs:build converts the whole sample collection, including the large directories. REFLOW_ENGINE and REFLOW_ALT_TEXT set the conversion options for that script.

Useful conversion switches

--no-page-images skips the renderings of the original pages but keeps the figure crops. --engine docling uses the full ML layout adapter. --alt-text local drafts figure descriptions with the local model. The defaults are --engine heuristic, --device auto, and --alt-text none.

08 / PROJECT STATUS

What exists, and what comes next.

The product spec describes a larger system than the code has today. This guide describes what the code does now, and lists the unfinished stages separately.

Implemented
  • The local CLI commands inspect, convert, convert-many, audit, and doctor.
  • PDF normalization, metadata, hashing, page classification, and OCR through OCRmyPDF.
  • Heuristic, Docling, and hybrid layout paths.
  • Shared semantic model and JSON serialization.
  • Static HTML chunks, page images, figure crops, and review reports.
  • Optional local figure descriptions, and opt-in model questions about form labels, headings, and scanned fields.
  • Web reader, review dashboard, visual inspector, "Ask a question", and conversion jobs.
  • An axe-core check of the web viewer (bun run a11y).
  • Python unit tests and opt-in real-document page checks.
Roadmap and unfinished work
  • Saved human corrections and deterministic overrides.
  • Accessibility and performance checks inside the conversion, with timing budgets.
  • A publishing gate based on resolved review and validation.
  • Hosted upload, job queue, and publishing service.
  • Prebuilt full-document search index.
  • Tagged PDF/UA export from the shared model.
How is conversion quality checked today?

The default pytest suite tests synthetic PDFs, the models, layout rules, rendering, and CLI behavior. The opt-in page-check suite checks real sample pages for text recall, reading order, headings, lists, tables, and figures. Known defects are strict expected failures. Run uv run pytest for the default tests, or uv run pytest -m pages -k fw9 for the page checks of the W-9.
